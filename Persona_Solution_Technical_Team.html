Precondition DetaylarıPrecondition Details

Rezervasyon oluşturmak için sırayla: 1) Zorunlu alanlar doldurulmalı 2) Uçuş/kapasite kontrolü 3) Embargo kontrolü (error ise dur, warning ise devam) 4) ACRM'den fiyat alınır, yoksa Commis tarife fiyatı kullanılır 5) Restriction kontrolü 6) Gerekirse Accuity'ye gönderilir (bu durumda consignee/shipper zorunlu) 7) Rezervasyon oluşturulur. To create reservation in order: 1) Mandatory fields filled 2) Flight/capacity check 3) Embargo check (stop if error, continue if warning) 4) Price from ACRM, if not available Commis tariff price used 5) Restriction check 6) If required sent to Accuity (consignee/shipper become mandatory) 7) Reservation created.

MoM Kanıtları:
• "If it is error level, the process cannot continue. If it is info/warning, the process continues" — MoM 2026-01-09
• "If ACRM does not return a price, the process continues with the Commis tariff price" — MoM 2026-01-09
• "If the destination must be sent to the Accuity system, consignee and shipper fields become mandatory" — MoM 2026-01-09

Entegrasyon DetaylarıIntegration Details

TK GO veya dijital kanallardan oluşturulan rezervasyonlar Commis sisteminde listelenir. Agent kullanıcılar Execute statüsüne kadar her veriyi güncelleyebilir. Execute sonrasında bile cancel yapabilirler. Uçuş değişikliğinde irregularity ve remark alanları zorunlu olur, tekrar ACRM'e gidilmesi gerekir. Reservations created from TK GO or digital channels are listed in Commis system. Agent users can update any data until Execute status. They can cancel even after Execute. When flight changes, irregularity and remark fields become mandatory, need to go to ACRM again.

MoM Kanıtları:
• "Agent users can update any reservation data without restriction until the reservation reaches Execute status" — MoM 2026-01-09
• "When an existing reservation's flight is changed via Commis, the irregularity and remark fields become mandatory" — MoM 2026-01-09

Rol KarmaşıklığıRole Complexity

Sistemde yaklaşık 104 farklı rol var. Bunların bir kısmı read-only, bir kısmı doğrudan rezervasyon oluşturabilir, bir kısmı sadece belirli alanları güncelleyebilir. Her rol grubu farklı iş ihtiyaçlarına göre tanımlanmış. Bu karmaşıklık, yeni özellik eklerken dikkatli rol analizi gerektiriyor. There are approximately 104 different roles in the system. Some are read-only, some can create reservations directly, some can only update specific fields. Each role group is defined according to different business needs. This complexity requires careful role analysis when adding new features.
